# Disposable Kubernetes lab

Requirements: Docker, kind, kubectl, Python and a `.env` generated by `scripts/setup_env.py`. Keep this in a local test cluster; no ingress or public LoadBalancer is provisioned.

```sh
docker compose build
kind create cluster --name velora
for name in auth-service user-service admin-service customer-service dashboard-service frontend; do
  kind load docker-image "velora/$name:local" --name velora
done
kubectl create namespace velora
kubectl -n velora create secret generic velora-secrets --from-env-file=.env
kubectl apply -f k8s/lab.yaml
kubectl -n velora wait --for=condition=Available deployment --all --timeout=300s
```

Use separate terminals for each port forward; stop Compose first if it uses the same host ports:

```sh
kubectl -n velora port-forward service/frontend 8080:8080
kubectl -n velora port-forward service/prometheus 9090:9090
kubectl -n velora port-forward service/jaeger 16686:16686
kubectl -n velora port-forward service/alert-sink 9095:9095
```

Then run `python scripts/smoke.py` and open `/observability`.

For a controlled outage, scale `deployment/auth-service` to zero, run `python scripts/smoke.py --alert firing`, restore one replica, wait for rollout, then run the resolved check. CI automates this with `scripts/test_kubernetes.sh`.

ConfigMaps contain monitoring settings and the local webhook receiver; a Secret supplies the database/JWT/internal API values. Kubernetes Secrets require cluster access controls and encryption configuration; base64 serialization alone is not encryption.

The database, trace storage, Prometheus data and webhook history are ephemeral. This lab is not a persistent production deployment and runs one replica per component. Application probes establish process/bootstrap readiness, not end-to-end dependency availability. PostgreSQL's initialization image is the exception to the application non-root policy.

Regenerate committed manifests after editing `compose.yaml`, `monitoring/` or the receiver:

```sh
python scripts/render_kubernetes.py
python scripts/render_kubernetes.py --check
```

Cleanup: `kind delete cluster --name velora` removes the cluster and its lab data.
